## 贯穿规则

1. 新的公开入口只接受「可读流 + 来源 ID」。来源 ID 由调用方分配，库不解释它。`searchFile`、`parallel.run` 的路径参数、以及事件里的服务器路径，留到 N7 从公共 API 去掉。
2. 匹配内核（`src/finder/`）继续只做字面量。行语义、预算、编码留在 Searcher。
3. 序列化不进 core。N6 之前，现有 JSON 打印器只作为测试夹具；N6 起，库不再把 NDJSON 或终端文本当作完成标准。
4. 每个节点合并前跑 `zig build test`。节点表里的旧测试必须仍然通过；行为按清单改掉时，改测试名和断言，不要删掉覆盖。
5. 禁止项用搜索确认，不靠「看起来没有」。搜索范围是 `src/`。
6. N11 之后，公共 API 以 `docs/API.md` 为准。代码和文档不一致时，节点不能通过。

## N1 单输入匹配语义

在现有 `searchSlice` / `searchReader` 上补齐字面量的行语义。输入仍然可以是内存切片。

不做：不改编码，不做超长行窗口，不加来源 ID，不改目录遍历。

| 清单 | 验收行为 |
|---|---|
| C02 | 行终止符仍是 LF。判定整行和返回行内容时去掉行尾的一个 `\r`。CRLF 输入上，整行匹配不再把 `\r` 算进行内容 |
| B06 | 每个模式单独做智能大小写：该模式全是小写才忽略大小写。文档写明这和 rg「整组里出现大写就全部区分大小写」不同。单模式行为保持现在的测试 |
| B07 | 整词匹配检查匹配前后的字符边界。半边界：`-2` 能命中 `(-2)`，不能命中 `x-2` 或 `-2y` |
| B08 | 整行匹配。与 B07 同时开启时只看整行。行尾 `\r` 已由 C02 去掉，不参与整行比较 |
| B02 | 多模式仍是 OR。构造前拒绝超出条数上限或总长度上限的模式列表。上限由调用方配置，库有硬顶 |
| I07 | 校验发生在分配自动机、Teddy 表或 Aho-Corasick 之前。超限返回类型化错误，不开始扫描 |
| B10 | 一个来源的匹配行数达到上限后，不再向上游读下一块。已经在缓冲里的 after 行可以交出去，但不能为此再 `read`。调用方提供关闭函数时，库在停止时调用它 |
| B12 | 一行必须同时满足全部「包含」和全部「不包含」才输出。这和 B09 的按行反选是两个开关，测试要同时打开它们 |

验证：

- 新增测试：
  - `CRLF 行内容不含 CR，整行匹配不把 CR 算进去`
  - `智能大小写按每个模式判断`
  - `整词的半边界`
  - `整行优先于整词`
  - `模式条数和总长度在构造前被拒绝`
  - `max_count 之后不再读上游`
  - `AND 与 NOT 同时过滤，且与反选不同`
- 必须仍通过：`切片：反选和反选上下文`、`ASCII 忽略大小写`、`换行、空模式、单字节、smart case`、`Reader 跨块保留半行`、`全是单字节时走字节集`、`邻接对放不下时走 Teddy 或自动机`。
- 改写 `切片：空行、无结尾换行、CRLF 保留 CR`：无结尾换行和空行的断言保留，CRLF 改为去掉 `\r`。
- 改写 `ASCII 忽略大小写，smart 看全部模式`：多模式改为逐条判断，并在 `matcher.zig` 的文档注释里写明与 rg 的差别。

退出：上表八项都有实现位置和测试名。B01、B03、B04、B09、B15 仍然 DONE。

## N2 行窗口、二进制、上下文

单行不再因为超长而失败。二进制默认跳过。上下文在不可回退的流上有界。

不做：不做 BOM 和 UTF-16。不引入 progress 事件。

| 清单 | 验收行为 |
|---|---|
| C08 | 超过单行上限的行继续按流查找。交出去的是匹配附近的窗口，事件标明已截断，并带原始行长和窗口在行内的位置。行起点的绝对字节偏移仍然精确。完全不匹配的超长行也不把缓冲涨过上限 |
| D02 | 三种模式都在：跳过、搜索但不返回内容、按文本处理。默认是跳过。检测到 NUL 时，结果里带 `binary_offset`。跳过模式在 NUL 处停止读取 |
| D03 | 按文本处理时，超长行仍走 C08 的窗口，不退回到 `error.LineTooLong` |
| E02 | 前置上下文用环形缓冲，容量是「上下文行数上限 × 单行上限」。不依赖 seek。缓冲满了以后丢掉最旧的行 |
| E03 | 有一个对称上下文设置。单独的前置或后置值覆盖对应的一侧 |
| E04 | 相邻上下文合并成一段，不重复发送。断点是结构化标记。core 和库内打印器都不输出 `--` 字符串 |
| E05 | 上下文行数有服务端上限，调用方可以把它调低，不能调过硬顶 |

验证：

- 新增测试：
  - `超长行只保留匹配窗口并且偏移精确`
  - `不匹配的超长行也不把缓冲涨过上限`
  - `二进制默认跳过并带 binary_offset`
  - `搜索二进制但不返回行内容`
  - `按文本处理的二进制仍走超长行窗口`
  - `前置上下文容量不超过行数上限乘单行上限`
  - `对称上下文可被单侧覆盖`
  - `断点是标记而不是两个减号`
  - `上下文行数不能超过硬顶`
- 必须仍通过：`切片：行号、上下文和分隔`（分隔断言改成结构化断点）、`切片：二进制 report 和 quit`、`Reader 跨块保留半行`、`外部停止标志让流式搜索不再读下一块`。
- `test "默认搜索配置"` 改为期望二进制默认是跳过。
- 在 `src/` 搜索 `--\n` 和 `context-separator`。生产代码无匹配。
- `zig build test` 通过。

退出：上表七项可判 DONE。E01 仍然 DONE。

## N3 编码与 UTF-16 偏移

在 N2 的行窗口之上做编码。原始字节模式必须能关掉转码。

不做：不做 GBK 和其他 WHATWG 编码（C06）。不做压缩后的原始偏移（F12）。

| 清单 | 验收行为 |
|---|---|
| C03 | 可以改用 NUL 作为记录分隔符。这种模式下按记录计数，记录里的 LF 不再断行。仍按文本处理，不把 NUL 当成二进制 |
| C04 | 只在流开头嗅探 BOM。识别 UTF-8、UTF-16LE、UTF-16BE。UTF-16 先转成 UTF-8 再搜索。非法序列替换为 U+FFFD。无 BOM 时不猜测编码 |
| C05 | 显式的原始字节模式不做任何转码，也不嗅探 BOM。非法字节原样进入匹配 |
| F05 | 每个匹配带 `u16_start`、`u16_end`，行带 `u16_column`。在扫描或转码时一次算完，不在回调里再扫一遍 |
| F06 | 含非法 UTF-8 的行同时给出有损文本（U+FFFD）及其 UTF-16 偏移，以及原始字节和字节偏移。原始字节可以由调用方再做 base64，库不强制编码 |

验证：

- 新增测试：
  - `NUL 分隔符按记录计数`
  - `UTF-8 BOM 被跳过且不参与匹配`
  - `UTF-16LE 与 UTF-16BE 转成 UTF-8 后命中`
  - `非法 UTF-16 变成 U+FFFD`
  - `原始字节模式不嗅探 BOM`
  - `匹配的 UTF-16 偏移按码元计数`
  - `非法 UTF-8 同时给出有损文本和原始字节`
- 必须仍通过：N2 的超长行窗口测试、`分块读把 NUL 并进查找`。NUL 作为二进制信号只在「LF 分行且不是原始记录模式」时生效，测试要写明这一点。
- 跨块：BOM 和 UTF-16 的一个码元被拆在两块时仍能识别。把这个断言放进 `UTF-16LE 与 UTF-16BE 转成 UTF-8 后命中`，读缓冲设得比 BOM 加一个码元还小。
- `zig build test` 通过。

退出：上表五项可判 DONE。C01、C07 仍然 DONE。

## N11 完整 API 文档

把 N7 结束时的公共 API 整理成一份文档。读者只看这份文档就能调用库，不必再读 `DESIGN.md` 或清单。

必须包含这些节：

| 节 | 写清什么 |
|---|---|
| 范围 | 库搜索调用方给出的流。不接收文件系统路径，不执行外部命令，不输出终端文本或 NDJSON |

| 二进制 | 三种模式和默认值，以及 `binary_offset`、二进制状态字段 |
| 上下文 | 前置、后置、对称覆盖、断点标记、行数上限 |
| 事件 | begin、match、context、progress、end、summary 的每个字段，包括行号、字节列号、绝对偏移、半开区间、UTF-16 偏移、截断、`limit_hit`、`partial`、来源 ID |
| 预算与错误 | 扫描字节、时间、取消、结果数、输出字节、内存上限。致命错误、来源软错误、有匹配、无匹配如何区分。返回给调用方的错误不含内部路径 |
| 默认值 | 服务层可以覆盖的项，以及不能打开的项：跟随符号链接、读取全局或父目录忽略 |
